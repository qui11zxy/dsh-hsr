# dsh-hsr

DeepSeek Harness 插件：查询《崩坏：星穹铁道》的角色、光锥与遗器资料。

装好之后，模型手里多一个 `hsr` 工具，问「三月七满级面板」「银河铁道之夜叠影五阶」「云无留迹的过客两件套效果」「欢愉命途都有谁」这类问题时会先查再答，不用凭记忆编数字。

## 它能给出什么

**角色**：星级、命途、属性、简介、80 级满级基础属性、行迹属性加成合计、各技能（按满级口径）、额外能力、星魂、忆灵、专属效果。

**光锥**：星级、命途、80 级满级基础属性、技能正文、叠影 1～5 阶参数对照。

**遗器套装**：名称、内圈或外圈、2 件套与 4 件套的套装效果。

**清单**：全部角色或光锥，按命途、属性、星级筛选；全部遗器套装，标注内外圈。

数据是每次调用现查的最新资料，不在本地留副本。

## 安装

插件以 bundle 形式挂到某个 DSH profile 上。假设 profile 目录是 `~/.dsh/profiles/desktop`：

```bash
cd ~/.dsh/profiles/desktop
npm install github:qui11zxy/dsh-hsr
```

然后在 `~/.dsh/profiles/desktop/package.json` 里把包名加进 bundles 列表：

```json
{
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "dsh-hsr"
      ]
    }
  }
}
```

重启 DSH，`hsr` 工具就绪，设置里会多出一栏「HSR 数据库」。

想装本地副本（自己改代码时方便）：

```bash
cd ~/.dsh/profiles/desktop
npm install file:/path/to/dsh-hsr
```

## 用法

工具只有一个参数 `args`，写一行 flag：

| 参数 | 说明 |
| --- | --- |
| `--role 名字` | 查角色，支持中文名、英文名、昵称 |
| `--lightcone 名字` | 查光锥 |
| `--relicset 名字` | 查遗器套装 |
| `--list` | 列清单，可与 `--role` / `--lightcone` / `--relicset` 同用 |
| `--baseType 命途` | 按命途筛选：毁灭、巡猎、智识、同谐、虚无、存护、丰饶、记忆、欢愉 |
| `--damageType 属性` | 按属性筛选，仅角色：物理、火、冰、雷、风、量子、虚数 |
| `--star 星级` | 按星级筛选，仅光锥：3、4、5 |
| `--lang 中\|英` | 输出语言，默认中文 |
| `--rule` | 返回使用规则与查询经验 |
| `--exp` | 只返回查询经验 |
| `--exp --team` | 只返回配队经验 |
| `--teamKnowledge` | 返回游戏规则的目录与全部配队经验，准备配队时用 |
| `--teamKnowledge --section 3` | 取游戏规则里的某一节（编号、标题都行，`--section all` 取全文） |

三种写法等价：`--role 三月七`、`--role=三月七`、`--role --三月七`。

### 例子

```
--role 三月七
--role 星神★阿哈
--role 三月七 --baseType 巡猎
--lightcone 当第一声「阿哈」响起
--relicset 云无留迹的过客
--relicset --list
--role --list --damageType 冰
--lightcone --list --star 5
--role 三月七 --lang en
--rule
--teamKnowledge
--teamKnowledge --section 3.6
```

同名角色（比如两个「三月七」）会返回其中一个，并在末尾列出全部同名条目，加 `--baseType` 或 `--damageType` 就能指定。

## 设置

设置里有一栏「HSR 数据库」：

- **代理**：留空跟随系统（浏览器）代理；填 `direct` 强制直连；也可以直接填 `127.0.0.1:7897` 这样的地址。
- **查询经验**：写你对角色的称呼与全称的对应关系（例如「板鸭 = 布洛妮娅」），模型查询时会先读这段。
- **配队经验**：写你的配队偏好、已有角色光锥遗器，模型给配队建议时会读这段。
- **删除本机自识别经验**：清空模型自己写下的检验经验，点击前会再确认一次。

这两段文字分别存到 `~/.dsh/dsh-hsr/experience/user.md` 与 `user-team.md`，也可以直接改文件。

## 数值口径

- 角色与光锥的属性都是 **80 级满级**值，角色已含突破成长，光锥由「起点值 + 每级增量 × 79」算出。
- 技能按「理论满级」折算：15 级表取 10 级，10 级表取 6 级，更短的逐级列出。
- 能量上限与该技能的回能取自数据源的 `sp_need` 与各技能的 `sp_base`，分别写在基础属性行和每个技能标题后。黄泉（残梦层数）、星神★阿哈（笑点）这类不靠能量条的角色数值远低于正常水平，这两项整块不显示，避免误读。
- 削韧值取自技能的 `show_stance_list`，三个位置依次是主目标、全体、相邻目标；单攻显示一个数，群攻标「全体」，扩散标「主目标 / 相邻」，弹射标「每段」。
- 忆灵的生命、速度会代入具体数值，并标出它继承自角色哪一项。
- 遗器套装只有 2 件套效果的是内圈，同时有 2 件与 4 件效果的是外圈。
- 富文本里的颜色、下划线、注音、`#1[i]` 之类的占位符都已替换成普通文字。

## 经验文件

经验分查询与配队两套，每套三层：

| 层 | 查询 | 配队 | 谁维护 |
| --- | --- | --- | --- |
| 基础经验 | 插件内 `experience/base.md` | 插件内 `experience/team-base.md` | 随插件发布，只读 |
| 模型检验 | `~/.dsh/dsh-hsr/experience/model.md` | `model-team.md` | 模型发现口径不对时自己写 |
| 用户经验 | `~/.dsh/dsh-hsr/experience/user.md` | `user-team.md` | 你自己写（设置页可填） |

普通查询不返回经验：`--rule` 带使用规则与查询经验，`--exp` 只看查询经验，`--exp --team` 只看配队经验，`--teamKnowledge` 带配队经验。文件首次读取时会自动建好。

游戏规则（`rules/game.md`）按知识库的方式给：`--teamKnowledge` 只返回二级/三级标题的目录（每节标了行数或子节数），模型看完目录再用 `--teamKnowledge --section 3.6` 取需要的那一节，不必每次把近三百行全塞进上下文。`--section` 接受编号（`3`、`3.6`）、标题片段（`伤害计算`、`击破`）或 `all`。

## 配置

`config/config.json` 里放着命途表、属性表、标签名、段落标题、默认语言和昵称写法。想改称呼或者补别名，改这个文件即可；命途与属性的可选值都从这里读，代码里没有硬编码。

`rules/rules.md` 是使用规则，`--rule` 会原样返回；`rules/game.md` 是配队用的游戏规则，`--teamKnowledge` 会带上它。后者留空，由你自己写。

## 要求

- Node.js 22 以上。
- 需要能访问外网，插件每次查询都实时取数；连不上时只会提示「无法连接，请检查网络连接或配置可用代理」，需要的话在设置里填代理。
